# UX Review Addendum: Navigation Cleanup

本輪已完成第一階段 IA / UX 清理：

- 首頁不再顯示七顆等權重大按鈕，改為分組式 compact navigation。
- `撤銷最後結帳` 已從首頁移除，降低誤操作風險。
- `訂單歷史`、`營運事件`、`庫存現況` 的命名更能區分 paid orders、businessEvents 與 inventoryLots。
- `資料與設定` 頁已拆成 `今日結帳／日結` 與 `資料備份與還原` 兩個視覺區塊。
- 首頁狀態區標題改為 `今日狀態`；Current Order 空白狀態改為 `尚未選擇訂單`，並提示從座位、外帶訂單或 Order Queue 開始。

仍待後續產品決策：

- `今日結帳` 與 `資料與設定` 目前導向同一頁不同區塊，尚未拆成獨立 view。
- 撤銷結帳目前只顯示最近一筆可撤銷訂單；若未來要支援指定歷史訂單逐筆撤銷，需再擴充歷史明細操作。

# UX Review

本文件只列出目前 UI / UX 觀察，不修改程式。角度以現場咖啡店 POS 操作效率為主。

## 目前好用的地方

- 首頁直接呈現座位、外帶、商品與訂單，不需要先進入管理或報表頁。
- 座位卡能看出佔用狀態、開單時間、停留時間與金額，現場巡桌時有幫助。
- 外帶訂單已經有獨立區塊，且可同時存在多張未結帳外帶單。
- 訂單明細分成出品清單與編輯訂單，能把製作流程與改單流程分開。
- 出品清單可以直接切換 served 狀態，適合吧台確認已出品項。
- 商品管理可直接在 POS 內新增、編輯、停售商品，不必改程式。
- 歷史頁與 Dashboard 都以已結帳訂單為基礎，對每日檢查營收與品項銷售有幫助。
- 備份 / 還原功能明確，正式營運前可匯出完整 JSON。

## 可能造成現場操作卡住的地方

- 內用開單使用 `window.prompt` 輸入人數；iPad 現場操作可能會跳出系統對話框，流程感較不連續。
- 有 variant 的商品使用 `window.prompt` 選擇口味 / 規格；忙碌時輸入錯誤會導致該次加入取消。
- 刪除品項、取消客人、結帳、撤銷結帳、匯入備份等多處使用 confirm；保護性高，但尖峰時段可能打斷節奏。
- 商品點選前必須先有 open order；若店員先點商品再選座位，會被擋下。
- 已結帳訂單可以轉回 open 編輯，這對修正錯誤有用，但也可能讓歷史與報表暫時變動。

## 可能多餘的點擊

- 內用開單至少需要點座位、輸入人數、確認 prompt，才開始點餐。
- 有 variant 的商品每次加入都需要額外 prompt；若熱門商品常有固定口味，點擊 / 輸入成本較高。
- 切換品項冰熱、內外帶、數量都在編輯訂單模式中；若目前停在出品清單，需要先切到編輯訂單。
- 現金結帳需要按結帳並確認，沒有快速收款或預設確認流程。
- Dashboard 自訂日期需要操作 date input；若現場只常看固定營業日，可能仍可接受。

## 可能容易誤操作的地方

- 已改善：`撤銷最後結帳` 不再是首頁全域動作，目前改為 `訂單歷史` 中的受控入口，按鈕會顯示可撤銷對象。
- 歷史訂單可刪除整張紀錄，若誤刪會影響報表；目前沒有看到回收站或 undo delete。
- 「編輯已結帳訂單」會把 paid order 轉回 open；若忘記重新結帳，該訂單會暫時不進入 Dashboard 與每日報表。
- 匯入備份會覆蓋 localStorage；雖有 confirm，但仍屬高風險動作。
- 備份頁有清空測試訂單資料；正式版若仍顯示，需特別確認現場權限與文案。

## 對外帶訂單的觀察

- 已有獨立 Takeout 區塊，包含新增外帶、未結帳外帶卡片、等待時間與金額。
- 外帶訂單不需要輸入人數，符合多數外帶流程。
- 外帶訂單使用同一個訂單面板編輯與結帳，操作邏輯與內用一致。
- 待確認：外帶訂單是否需要顯示取餐號、客名或電話；目前程式未看到這些欄位。
- 待確認：外帶完成但未結帳、已付款但未取餐等狀態是否符合現場流程；目前只有 open / paid 與 served 品項狀態。

## 對結帳流程的觀察

- 現金結帳流程簡單，適合先快速落地。
- 目前沒有收到金額與找零，若現場需要收現找零，店員仍需心算或用其他工具。
- 目前付款方式固定為 cash，若有轉帳、Line Pay、刷卡等，需要後續擴充。
- Undo checkout 限制 5 分鐘，可降低長時間回改造成報表不穩定，但現場若晚發現錯誤可能需要用「編輯已結帳訂單」處理。

## 對出品流程的觀察

- 出品清單以類型分組並可標記 served，對吧台製作很直接。
- served 是品項層級狀態，數量大於 1 時仍是一整行品項狀態；待確認是否需要支援部分出品。
- 出品清單與編輯訂單切開是好事，但若店員需要邊出品邊改冰熱 / 數量，會多一次切換。
- 商品備註目前只在商品管理看到，訂單品項雖有 `note` 欄位但未看到輸入 UI；特殊需求可能無法傳達到出品清單。

## 對 Dashboard 的觀察

- Dashboard 已包含商品排行、類別、冰熱、座位與時段，對每日復盤足夠實用。
- 可切今日、昨日、七天、本月與自訂日期，覆蓋常見檢查情境。
- Dashboard 只看 paid orders，因此 open order 不會干擾已完成營收。
- 商品排行目前顯示前 8 名；待確認是否足夠，若商品數增加可能需要完整列表或匯出。
- 目前 Dashboard 看起來是表格型分析，沒有圖表；對行動裝置快速掃描是否足夠待現場測試。

## 已知待改善方向檢查

- 外帶訂單是否需要獨立 Takeout 區塊：已實作獨立區塊，但是否需要更像看板式取餐流程仍待確認。
- 是否需要顯示客人已坐幾分鐘：已實作內用停留時間與外帶等待時間，且座位有 60 / 90 分鐘警示 class。
- 商品是否需要備註：商品管理已有商品備註；訂單品項 note 欄位存在，但目前未看到點餐時輸入品項備註的 UI。
- 結帳是否需要輸入收到金額並自動找零：目前未實作。
- 商品是否需要「今日停售」：商品管理已有停售 / 恢復，效果是全域 active 狀態；是否只限今日、隔日自動恢復，未實作。
- 是否能減少點擊次數：可改善，尤其是人數 prompt、variant prompt、結帳 confirm、出品 / 編輯切換。

## 建議優先改善順序

1. 收款找零：現金店務最常遇到，能直接降低結帳錯誤。
2. 商品備註 / 品項備註：支援少冰、少糖、分裝、客製需求等現場溝通。
3. 操作效率優化：先處理人數輸入、variant 選擇與常用動作點擊數。
4. 今日停售：若商品售完頻繁，需比商品管理的長期停售更貼近當日營運。
5. 外帶區塊強化：已有基礎區塊，下一步可確認是否需要取餐號、客名、付款 / 取餐狀態。
6. 停留時間顯示優化：已實作，下一步可調整視覺優先級與警示門檻。
