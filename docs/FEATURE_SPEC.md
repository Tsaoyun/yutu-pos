# Feature Spec

本文件只整理下一階段已知要做的功能規格，不自行新增其他功能。狀態依目前程式碼判斷。

## Takeout 外帶訂單獨立區塊

### 目前狀態

Partial

### 目的

讓外帶訂單不被內用座位流程綁住，店員可以快速新增、查看與切換多張未結帳外帶單。

### 建議 UI

目前首頁座位區下方已有外帶訂單區塊。下一階段若要強化，建議仍放在座位區附近，讓店員進入 POS 後第一眼同時看到內用與外帶待處理訂單。

### 資料影響

- 目前已有 `seatId: "takeout"` 與外帶虛擬座位。
- 可能需要新增外帶識別資訊，例如取餐號、客名、電話或取餐狀態。待確認。
- 若要區分已付款未取餐，可能需要新增訂單狀態或外帶 fulfillment 欄位。待確認。

### 驗收條件

- 可從首頁新增外帶訂單。
- 可同時存在多張未結帳外帶訂單。
- 外帶訂單卡片可顯示建立時間、等待時間、品項摘要與金額。
- 點外帶卡片可切換到該訂單明細。
- 外帶訂單新增品項時，品項預設為外帶。

## 客人停留時間顯示

### 目前狀態

Implemented

### 目的

讓現場快速判斷客人已坐多久、外帶客人已等多久，協助服務提醒與翻桌判斷。

### 建議 UI

目前座位卡與訂單明細已顯示停留 / 等待分鐘，外帶卡片也顯示等待時間。下一階段可檢查字級、顏色與警示門檻是否符合現場習慣。

### 資料影響

- 目前直接由 `createdAt` 與目前時間，或 `checkedOutAt` 計算，不需要新增欄位。
- 已有 60 / 90 分鐘警示 class；警示門檻是否可配置待確認。

### 驗收條件

- open 內用座位顯示已坐幾分鐘。
- open 外帶訂單顯示已等幾分鐘。
- paid order 顯示停留分鐘。
- 停留時間會隨 render 依目前時間重新計算。
- 超過既定門檻時有可辨識的視覺提示。

## 商品備註

### 目前狀態

Partial

### 目的

支援現場對商品或單筆品項記錄特殊需求，降低口頭溝通遺漏。

### 建議 UI

商品管理目前已有商品備註欄，可保留在商品表單中。品項備註若要加入，建議放在訂單「編輯訂單」模式的每個品項下方，避免干擾出品清單主流程；出品清單則只顯示已輸入的備註。

### 資料影響

- 商品已有 `product.note`。
- 訂單品項已有 `item.note` 欄位，但目前未看到點餐 UI 可輸入。
- 可能需要新增品項備註輸入、保存與出品顯示邏輯。

### 驗收條件

- 商品管理可輸入並保存商品備註。
- open order 的單筆品項可輸入備註。
- 品項備註會保存在 order item。
- 出品清單能看到品項備註。
- 結帳、歷史訂單、JSON backup / restore 後備註仍保留。

## 收款找零

### 目前狀態

Not Implemented

### 目的

讓現金結帳時可輸入客人實收金額，自動計算找零，降低心算錯誤與結帳時間。

### 建議 UI

建議放在現金結帳按鈕附近或結帳 confirm 前的收款區。可顯示應收、收到、找零，並保留快速金額按鈕。實際 UI 待確認。

### 資料影響

- 目前 order 只有 `paymentMethod` 與 `checkedOutAt`。
- 可能需要新增 `amountReceived`、`changeDue` 或 payment detail 欄位。
- 是否需要保存付款方式細節、找零紀錄與更正紀錄待確認。

### 驗收條件

- 結帳前顯示應收總額。
- 可輸入收到金額。
- 系統自動顯示找零。
- 收到金額小於應收時不可完成現金結帳，或需明確提示。
- 結帳後歷史訂單可查看收款與找零資訊。
- JSON backup / restore 會保留收款資訊。

## 今日停售

### 目前狀態

Partial

### 目的

當日商品售完或暫停供應時，店員可快速停賣，避免誤點已無法供應的商品。

### 建議 UI

目前商品管理已有停售 / 恢復按鈕。若要做「今日停售」，建議在商品管理列表保留長期停售，並在點餐商品按鈕或快速管理區提供今日停售切換。實際位置待確認。

### 資料影響

- 目前已有 `product.active`，屬於全域販售狀態。
- 今日停售可能需要新增 `soldOutToday`、`pausedUntilDate` 或每日覆寫狀態。待確認。
- 是否隔日自動恢復待確認。

### 驗收條件

- 店員可將商品標記為今日停售。
- 今日停售商品不能被加入新訂單。
- 已在訂單中的品項不應被自動刪除。
- 今日停售狀態與長期停售狀態可被清楚區分。
- 隔日是否自動恢復依確認後規則執行。

## 操作效率優化

### 目前狀態

Partial

### 目的

減少現場尖峰時段的點擊、輸入與確認成本，讓點餐、改單、出品、結帳更快完成。

### 建議 UI

優先檢查首頁點餐流程。可針對人數輸入、variant 選擇、出品 / 編輯切換、結帳流程做更直接的 inline 控制。具體設計待確認。

### 資料影響

- 多數效率優化可能只改 UI，不一定新增資料欄位。
- 若加入預設人數、常用 variant、快捷收款金額，可能需要新增偏好設定。待確認。

### 驗收條件

- 內用開單流程比目前 prompt 更快，且仍能保存人數。
- 有 variant 的商品可更快選擇口味 / 規格。
- 常用改單動作不需要在出品清單與編輯模式之間反覆切換，或切換成本明顯降低。
- 現金結帳流程可在不犧牲確認安全的情況下減少操作時間。
- 現場測試時，完成一張典型內用單與一張典型外帶單的點擊數下降。
